# Paperless Assistant

ИИ-ассистент поддержки для [Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx). Он отвечает пользователям и инженерам на вопросы о функциях и ошибках программы по документации и исходному коду, смотрит в живой экземпляр Paperless через API (только чтение) и передаёт сложные обращения человеку.

> **Статус: этап 2 — ответы со ссылками.** Ассистент отвечает по-русски в веб-чате, через `make ask` и `POST /ask`. Каждая ссылка в ответе проверена кодом, а если ответа нет, он честно говорит «не нашёл». На 32 эталонных кейсах точность ссылок 0.93, честный отказ вне области 0.97, ложных отказов нет ([качество](#качество-ответов), [где ошибается](#где-ассистент-ошибается)). План этапов — [ниже](#план).

## Как это устроено

```
 Telegram-бот / HTTP API
          │
          ▼
 ┌──────────────────────────── assistant (FastAPI) ────────────────────────────┐
 │ роутер вопроса ─► поиск (векторный + точный) ─► ответ ─► проверка ссылок     │
 │        └─► инструменты Paperless (только чтение)        эскалация ─► Telegram │
 │ маскирование ПДн · журнал · метрики Prometheus · роли                        │
 └──────────────────────────────────────────────────────────────────────────────┘
          │                         │                              │
       Qdrant              исходники форка (тег)            Paperless-ngx (demo)
  (индекс доки и кода)   для точного поиска строк          REST API, тестовые документы
```

База знаний — документация и код Paperless-ngx на теге [`v3.4.2`](https://github.com/MichaelZhdanov/paperless-ngx-rag/tree/v3.4.2) форка. Demo-экземпляр запускается из образа той же версии, поэтому код в индексе совпадает с кодом, который работает в контейнере.

Это не то же самое, что встроенный в Paperless `paperless_ai`. Тот делает RAG по *документам пользователя*: подсказывает теги и отвечает по их содержимому. Этот ассистент — *поддержка*: он отвечает по документации и коду самого Paperless и разбирает его ошибки.

## Быстрый старт

Нужны Docker с Compose v2 и make.

```sh
make up
```

При первом запуске `make up` создаёт `.env` из `.env.example`: случайные секрет Paperless, пароль администратора, пароль входа в ассистента и ключ сессии подставляются сами. В уже существующий `.env` команда только дописывает секреты, которых там нет. Затем поднимаются все сервисы, и команда ждёт, пока их healthcheck станут зелёными. Первый старт Paperless (миграции базы) занимает до пары минут.

| Сервис | Адрес |
|---|---|
| Paperless | http://localhost:8000, логин и пароль — `PAPERLESS_ADMIN_USER` и `PAPERLESS_ADMIN_PASSWORD` в `.env` |
| Ассистент | http://localhost:8080/ — веб-чат, описание API — http://localhost:8080/docs. Вход — `WEB_LOGIN` и `WEB_PASSWORD` из `.env`, `NO_AUTH=1` выключает его. Если 8080 занят, задайте другой порт в `.env`: `ASSISTANT_PORT=8081` |
| Qdrant | http://localhost:6333/dashboard |

`make down` останавливает стек, данные остаются в томах Docker. Удалить и их: `docker compose down -v`.

Для ответов нужны два ключа в `.env`: `CLOUD_RU_API_KEY` для поиска ([ниже](#поиск-по-документации-и-коду)) и `GIGACHAT_API_KEY` для генерации ([ниже](#ответы-со-ссылками)). Ещё нужно один раз выполнить `make index`.

## Поиск по документации и коду

**Что в индексе.** Индексируется вся документация `docs/*.md`, включая changelog, и Python-код `src/` без тестов и миграций, на теге `v3.4.2`. Всего 3413 кусков:
- документация режется по заголовкам, якоря совпадают с docs.paperless-ngx.com;
- код режется через `ast` по функциям, методам и частям классов.

У каждого куска есть путь, строки, заголовок и ссылка на форк на нужных строках, у документации — ещё и ссылка на страницу сайта.

**Эмбеддинги.** Используется [cloud.ru Evolution Foundation Models](https://cloud.ru/products/evolution-foundation-models), модель `ai-sage/Giga-Embeddings-instruct-3B`. Она выбрана сравнением четырёх моделей ([ниже](#качество-поиска)). Векторы хранятся в Qdrant. Перед отправкой в API каждый текст проходит маскирование персональных данных: e-mail, телефоны, паспорт, СНИЛС, ИНН, номера карт. Провайдер и модель меняются переменными `EMBEDDING_PROVIDER` и `EMBEDDING_MODEL`; второй провайдер — Voyage AI.

**Что нужно для запуска:**
1. Ключ cloud.ru. В [консоли](https://console.cloud.ru) создайте сервисный аккаунт **уровня «Проект»**, в нём API-ключ для Foundation Models. Запишите ключ в `.env` как `CLOUD_RU_API_KEY`.
2. Деньги на балансе. Бонусы на модели не тратятся. Полная индексация стоит около 27 ₽, вопрос — доли копейки.

```sh
make index                                       # скачать тег, нарезать, посчитать эмбеддинги (~2 мин)
make search Q="почему не распознаётся русский текст"   # найденные куски, без LLM
make ask Q="почему не распознаётся русский текст"      # ответ GigaChat со ссылками, нужен GIGACHAT_API_KEY
make eval STAGE=retrieval                        # recall@5 на эталонных кейсах, отчёт в evals/reports/
```

Индекс хранит, по какому тегу и какой модели он построен. Если в настройках другой тег или другая модель, поиск отказывается работать и просит выполнить `make index`, а не молча отвечает по старым данным.

- Qwen3 на cloud.ru с инструкцией из своей карточки ищет хуже, чем без неё: 0.35 против 0.75. Поэтому инструкция к вопросу включается только там, где помогает на eval.

## Ответы со ссылками

`make ask`, веб-чат и `POST /ask` отвечают по-русски. Каждое утверждение ответа подкреплено цитатой, и наличие цитаты в источнике проверил **код**, а не модель. Если подтверждённых утверждений нет, ассистент честно отвечает «не нашёл» и показывает найденные куски.

```
вопрос ─► поиск топ-5 ─► промпт: куски в <source id=N>, маскирование ПДн, экранирование
       ─► GigaChat-2-Pro: JSON {status, statements:[{text, citations:[{source, quote}]}]}
       ─► citations.py: каждая цитата ищется в тексте, который видела модель
       ─► утверждение без подтверждённой цитаты удаляется; имена параметров обязаны быть в источнике
       ─► ответ: утверждения [n], источники (строки цитаты на форке, страница документации), пометка GigaChat
          или «не нашёл» + 3 найденных куска
```

- **Проверка ссылок** (`assistant/generation/citations.py`). Модель обязана скопировать фрагмент источника дословно. Код ищет его в тексте, который модель видела.
  - Оформление выравнивается: пробелы, кавычки, `**`, курсив, ссылки Markdown. Слова должны совпасть.
  - Цитата из одного заголовка или короче 3 слов не засчитывается.
  - Имена из утверждения (`PAPERLESS_…`, `manage.py …`) обязаны быть в процитированном куске. Так ловится выдуманный параметр.
  - Ссылка в ответе ведёт ровно на строки цитаты.
- **Термины.** Известные неверные переводы исправляет код после проверки ссылок. Например, Docker volume — «том», а не «объём». Исправление делается по глоссарию `assistant/generation/glossary.tsv`, его термины Paperless взяты из официального перевода интерфейса.
- **Порога по score поиска нет.** Решение «ответа нет» принимает модель, а код проверяет подтверждение. Подбирать порог на 32 кейсах значило бы подгонять его под них.

**Что нужно для запуска.**
1. Ключ GigaChat. В [личном кабинете](https://developers.sber.ru/studio) откройте проект GigaChat API → Настройки API → Получить ключ. Запишите его в `.env` как `GIGACHAT_API_KEY`. Бесплатный тариф Freemium подходит.
2. Сертификат не нужен. TLS GigaChat подписан НУЦ Минцифры, и корневой сертификат лежит в репозитории (`assistant/generation/certs/`, тест сверяет отпечаток). Им пользуется только клиент GigaChat: в систему сертификат не ставится.

```sh
make index                                         # один раз: индекс в Qdrant
make ask Q="почему не распознаётся русский текст"  # ответ в консоли
make up                                            # веб-чат: http://localhost:8080/
# API — после входа (или с NO_AUTH=1): cookie сессии в файле jar
curl -s -c jar -X POST localhost:8080/login -H 'Content-Type: application/json' \
     -d '{"login": "admin", "password": "<WEB_PASSWORD из .env>"}'
curl -s -b jar -X POST localhost:8080/ask -H 'Content-Type: application/json' \
     -d '{"question": "как подключить Paperless к 1С"}'   # тот же ответ в JSON
```

### Качество ответов

32 кейса dev — 12 howto, 8 config и 12 out_of_scope (ответа нет ни в документации, ни в коде) — по 3 прогона. Кейсы писали независимые субагенты до кода генерации ([как](evals/dataset/README.md)). У каждой доли 95% интервал Уилсона.

| Метрика | Порог | dev | отложенная выборка |
|---|---|---|---|
| точность ссылок (citation accuracy) | ≥ 0.90 | **0.93** (261/282, ДИ 0.89–0.95) | 0.87 ❌ (103/118) |
| честный отказ вне области (abstention) | ≥ 0.90 | **0.97** (35/36, ДИ 0.86–1.00) | 1.00 (24/24) |
| ложный отказ в области (false refusal) | ≤ 0.10 | **0.00** (0/60, ДИ 0.00–0.06) | 0.00 (0/30) |

| ответ ссылается на ожидаемый источник | — | 1.00 (60/60) | 1.00 (30/30) |
| негативный контроль: цитата у чужого источника | ≈ 0 | 0/282 | 3/118, дубли в коде Paperless |

- **dev** — промпт `answer_v1`, проверка цитат с исправленной нормализацией, судья GigaChat-3-Ultra: [итоговый отчёт](evals/reports/2026-11-04-gigachat-2-pro-final.md).
- **Отложенная выборка** — 18 кейсов, прогнана один раз, когда всё уже было выбрано: [отчёт](evals/reports/2026-11-04-holdout.md).
- **Выбор модели** (Lite отброшен: в половине прогонов пустой ответ) и **опыт с глоссарием** — в [сводке](evals/reports/2026-11-04-llm.md).

**Насколько этому верить.**
- **Судья.** Его проверяют канарейки: 8 из 8 тонко неверных утверждений пойманы. Ещё автор слепо разметил 78 утверждений: совпадение с судьёй 0.87, но каппа Коэна около 0. Судья строже человека по деталям и слабее его в терминах ([отчёт](evals/reports/2026-11-04-gigachat-2-pro-rescore-manual.md)).
- **Точность ссылок на отложенной выборке — 0.87, ниже порога.** Нормализацию цитат исправляли, глядя на dev. Все промахи на отложенной выборке — неточности модели (склейки через «...», лишнее слово). Порог не меняли.
- **Грамотность** оценивает отдельный вызов судьи. Канарейки он ловит 8 из 8, но на живых ответах придирчив, поэтому метрика показывается без порога.
- Судья недетерминирован даже при температуре 1e-4: ±0.02 между проходами по одним и тем же ответам.

### Где ассистент ошибается

- **Подставляет значения, которых нет в источнике:** `rus`, `Europe/Moscow`. По сути они верны, но не подтверждены цитатой, а код проверяет только имена, не значения.
- **Цитирует неточно.** Склеивает два места через «...» или добавляет слово. Такие утверждения удаляются, поэтому ответ получается короче, чем мог бы.
- **Ловушки «почти по теме».** На вопрос про ротацию логов Docker в одном прогоне из трёх ответил про `PAPERLESS_LOGROTATE_*`, а это логи самого Paperless.
- **Подаёт старую запись changelog как текущее состояние.**
  - На вопрос про Kubernetes ассистент ответил «можно использовать Helm-чарт, которым теперь управляет команда». Это запись версии 1.10.2, а в 1.12.0 чарт удалён.
  - Цитата настоящая, поэтому ни проверка кодом, ни судья такое не ловят.
  - Исправление — в следующей итерации: сначала кейсы «устаревший changelog» от независимого субагента.
- **Переводит термины по-своему.** Известные ошибки исправляет код, неизвестные — нет.
- **Отвечает медленно** на Freemium: p95 — 20 с.

### Как проверяется качество

| Что поменяли | Команда | Время |
|---|---|---|
| любой код, PR | `make test`, в CI — гейт точности ссылок на сохранённых ответах модели | секунды |
| проверку цитат, отчёт | `make eval ARGS="--rescore evals/reports/raw/<прогон>.json --no-judge"` — без генерации | секунды |
| поиск | `make eval STAGE=retrieval` — без GigaChat | ~1 мин |
| промпт, модель | `make eval ARGS="--sample 12 --runs 1"` — 12 кейсов поровну из категорий | ~3 мин |
| закрытие этапа | `make eval` — 32 кейса × 3, судья | ~25 мин |
| раз в итерацию | `make eval SPLIT=holdout` — отложенная выборка | ~15 мин |

## Деплой на сервер

```
git push main / Actions → CI → Run workflow
  └─ check (lint, тесты, сборка) ─► deploy: ssh root@сервер deploy/deploy.sh <SHA>
        └─ deploy/deploy.sh: логин и пароль → .env, git checkout <SHA>, make up,
           исходники Paperless и индекс, если их нет, проверка /health

https://<домен> ─► nginx (Let's Encrypt, limit_req на /login) ─► 127.0.0.1:8080 ассистент
systemd-таймер раз в сутки ─► deploy/refresh.sh: исходники и индекс, если их нет
```

Снаружи открыт только ассистент, и то после входа. Paperless и Qdrant слушают только `127.0.0.1`.

**Один раз на сервере** (Ubuntu или Debian, A-запись домена уже указывает на сервер, порты 22, 80 и 443 открыты):

1. На своей машине создать ключ деплоя без пароля, любого типа: `ssh-keygen -f deploy/deploy.key -N ''`. Оба файла ключа в `.gitignore`, тест это проверяет. Скопировать на сервер: `scp deploy/deploy.key.pub deploy/bootstrap.sh root@<домен>:`.
2. На сервере от root: `bash bootstrap.sh <домен> <e-mail> deploy.key.pub`, скрипт — [`deploy/bootstrap.sh`](deploy/bootstrap.sh). Он:
   - ставит Docker, nginx и certbot;
   - клонирует репозиторий в `/opt/paperless-assistant`;
   - дописывает ключ деплоя в `/root/.ssh/authorized_keys`, остальные ключи не трогает;
   - создаёт `.env`, получает сертификат и включает таймер.

   В конце печатает строку для `DEPLOY_KNOWN_HOSTS`.
3. Вписать ключи API в `/opt/paperless-assistant/.env`: `CLOUD_RU_API_KEY` и `GIGACHAT_API_KEY`. В GitHub они не хранятся.
4. В GitHub → Settings → Environments → `production` завести:

   | Что | Имя | Значение |
   |---|---|---|
   | секрет | `DEPLOY_HOST` | домен сервера |
   | секрет | `DEPLOY_SSH_KEY` | содержимое `deploy/deploy.key`, целиком, вместе со строками `-----BEGIN…` и `-----END…` |
   | секрет | `DEPLOY_KNOWN_HOSTS` | строка, которую напечатал bootstrap |
   | секрет | `WEB_PASSWORD` | пароль входа в чат |
   | переменная | `WEB_LOGIN` | логин входа, по умолчанию `admin` |

5. Push в `main` или Actions → CI → Run workflow. Первый деплой строит индекс: около 27 ₽ на cloud.ru и пара минут.

Почему так:
- **Деплой идёт от root** по ключу деплоя с полным доступом: сервер служит не только хостингом. `bootstrap.sh` дописывает ключ в `authorized_keys`, остальные ключи root не трогает.
- **На сервер едет ровно тот SHA, который прошёл проверку,** а не «последний main на момент деплоя».
- **Пароль входа уходит через stdin ssh,** а не аргументом команды: аргументы на сервере видны в `ps`. `scripts/set_env.py` пишет в `.env` только `WEB_LOGIN` и `WEB_PASSWORD`.
- **Таймер следит только за текущим тегом** `PAPERLESS_REF`: скачивает исходники и строит индекс, если их нет. Новые релизы Paperless не подхватываются сами: тег меняется осознанно, вместе с прогоном eval.
- **Ключ GigaChat у сервера и у локального eval общий,** а на Freemium запросы идут в один поток. Пока идёт `make eval`, чатом на сервере лучше не пользоваться. Прерванный прогон продолжается с `--resume`.

## Безопасность, которая есть уже сейчас

- Секреты лежат только в `.env`, а он в `.gitignore` и `.dockerignore`. В коде секреты хранятся как `SecretStr` и не видны в `repr` и логах, это проверяется тестами.
- Каждый сервис в compose получает только свои переменные. Ассистент не видит ни секрет Paperless, ни пароль администратора, это тоже проверяется тестом.
- Порты опубликованы только на `127.0.0.1`.
- Вход в чат и API по логину и паролю из окружения ([`assistant/security/auth.py`](assistant/security/auth.py)). Cookie сессии подписана (Starlette `SessionMiddleware`), у неё флаги Secure, HttpOnly и SameSite=strict. Смена пароля выкидывает всех. Если вход включён, но пароля нет, сервис не стартует. Перебор пароля ограничивает nginx.
- Всё, что уходит во внешние API (эмбеддинги и GigaChat), сначала проходит маскирование ПДн. Маскирование стоит внутри адаптера, поэтому обойти его нельзя. Тест проверяет само тело HTTP-запроса. Номера карт, ИНН и СНИЛС маскируются только с верной контрольной суммой, чтобы не трогать версии, порты и хеши в коде.
- Клиент GigaChat доверяет только корню НУЦ Минцифры из репозитория, тест сверяет отпечаток сертификата. В систему, certifi и `SSL_CERT_FILE` сертификат не ставится, проверка TLS не отключается.
- Найденные куски документации идут в промпт отдельными блоками. Кусок не может закрыть свой блок (`</source>` экранируется), а промпт велит считать их данными, а не инструкциями. Полная защита от промпт-инъекций с тестами-ловушками — этап 7.
- `POST /ask` при сбое зависимости отвечает 503 с короткой причиной, а подробности (адреса, ответы API) пишет только в лог.
- Страница чата загружает скрипты и стили только со своего адреса (CSP без CDN и встроенных скриптов) и вставляет ответ модели как текст, а не как HTML.
- Контейнер ассистента работает не от root.
- Инструменты для Paperless будут только читающими, с отдельным пользователем без прав на запись (этап 5).
