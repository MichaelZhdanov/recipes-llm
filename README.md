# Paperless Assistant

ИИ-ассистент поддержки для [Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx). Он отвечает пользователям и инженерам на вопросы о функциях и ошибках программы по документации и исходному коду, смотрит в живой экземпляр Paperless через API (только чтение) и передаёт сложные обращения человеку.

> **Статус: этап 0 — скелет.** Стек поднимается одной командой. У ассистента пока есть только `/health`, на вопросы он ещё не отвечает. План этапов — [ниже](#план).

## Как это устроено

```
 Telegram-бот / HTTP API
          │
          ▼
 ┌──────────────────────────── assistant (FastAPI) ────────────────────────────┐
 │ роутер вопроса ─► поиск (векторный + точный) ─► ответ ─► проверка ссылок     │
 │        └─► инструменты Paperless (только чтение)        эскалация ─► Telegram │
 │ маскирование ПДн · журнал · метрики Prometheus · роли                        │
 └──────────────────────────────────────────────────────────────────────────────┘
          │                         │                              │
       Qdrant              исходники форка (тег)            Paperless-ngx (demo)
  (индекс доки и кода)   для точного поиска строк          REST API, тестовые документы
```

База знаний — документация и код Paperless-ngx на теге [`v3.4.2`](https://github.com/MichaelZhdanov/paperless-ngx-rag/tree/v3.4.2) форка. Demo-экземпляр запускается из образа той же версии, поэтому код в индексе совпадает с кодом, который работает в контейнере.

Это не то же самое, что встроенный в Paperless `paperless_ai`. Тот делает RAG по *документам пользователя*: подсказывает теги и отвечает по их содержимому. Этот ассистент — *поддержка*: он отвечает по документации и коду самого Paperless и разбирает его ошибки.

## Быстрый старт

Нужны Docker с Compose v2 и make.

```sh
make up
```

При первом запуске `make up` создаёт `.env` из `.env.example`: случайные секрет Paperless и пароль администратора подставляются сами. Затем поднимаются все сервисы, и команда ждёт, пока их healthcheck станут зелёными. Первый старт Paperless (миграции базы) занимает до пары минут.

| Сервис | Адрес |
|---|---|
| Paperless | http://localhost:8000, логин и пароль — `PAPERLESS_ADMIN_USER` и `PAPERLESS_ADMIN_PASSWORD` в `.env` |
| Ассистент | http://localhost:8080/health, описание API — http://localhost:8080/docs |
| Qdrant | http://localhost:6333/dashboard |

`make down` останавливает стек, данные остаются в томах Docker. Удалить и их: `docker compose down -v`.

## Разработка

Нужен [uv](https://docs.astral.sh/uv/), он сам поставит Python 3.14.

```sh
make test     # pytest
make lint     # ruff check, ruff format --check, mypy --strict
make format   # автоформатирование
make help     # все команды
```

## Безопасность, которая есть уже сейчас

- Секреты лежат только в `.env`, а он в `.gitignore` и `.dockerignore`. В коде секреты хранятся как `SecretStr` и не видны в `repr` и логах, это проверяется тестами.
- Каждый сервис в compose получает только свои переменные. Ассистент не видит ни секрет Paperless, ни пароль администратора, это тоже проверяется тестом.
- Порты опубликованы только на `127.0.0.1`.
- Контейнер ассистента работает не от root.
- Инструменты для Paperless будут только читающими, с отдельным пользователем без прав на запись (этап 5).
