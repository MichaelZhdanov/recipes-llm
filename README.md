# Recipes LLM

ИИ-ассистент по рецептам в Telegram. Он подбирает рецепты из [датасета povarenok.ru](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) по вопросу на обычном языке («что-нибудь с курицей, но без молока»), отвечает со ссылками, которые проверяет код, смотрит остатки продуктов в Grocy и передаёт сложные обращения живому человеку в том же Telegram.

> **Статус: этап 3 — ответы со ссылками, проверенные дважды.** Claude Haiku 5.5 разбирает вопрос в фильтры, ищет по всем 145 954 рецептам и отвечает живым языком утверждениями с дословными строками рецепта. Код проверяет цитаты, а Claude Sonnet — смысл каждого утверждения до отправки: «нет» — одна доработка Haiku по замечаниям, «нет» и тогда — утверждение удаляется ([ответы со ссылками](#ответы-со-ссылками)). Поиск с фильтрами выполняет условия «с чем и без чего» у 92 % найденных рецептов против 56 % у одних векторов ([поиск с фильтрами](#поиск-с-фильтрами)). Бот — следующий этап ([план](#план)). Каркас перенесён из прошлого проекта ассистента поддержки Paperless-ngx; история git сохранена целиком.

## Как это устроено

```
Telegram ─► бот (этап 4) ─► разбор вопроса: Claude Haiku → search_recipes(запрос, include[], exclude[])
                              ├─ имена из словаря индекса: «картошка» → «картофель»
                              ├─ фильтр Qdrant: все include есть, ни одного exclude
                              └─ векторы: похожесть по названию и смыслу, топ-5 из 145 954
         ─► ответ Haiku: вступление + утверждения, у каждого — дословная строка рецепта
         ─► код: цитата — целая строка рецепта, числа — только из неё; иначе утверждение удаляется
         ─► Claude Sonnet проверяет смысл: «нет» → одна доработка Haiku по замечаниям → Sonnet снова
            → «нет» удаляется; ничего не осталось → «не нашёл» с подсказками
         ─► ссылки на povarenok.ru
эскалация (этап 5) ─► группа операторов: одна тема — одно обращение, бот пересылает сообщения в обе стороны
```

- **Фильтры, а не только векторы.** «Без молока» векторный поиск не понимает. Модель разбирает вопрос в списки «с чем» и «без чего», а Qdrant отбрасывает неподходящие рецепты до ранжирования.
- **Стиль свободный, факты — только из рецепта.** Ответ живой, на «вы», с эпитетами и эмодзи, но каждое утверждение опирается на строку рецепта, и это проверяет код, а смысл — вторая модель. Шагов приготовления в датасете нет, поэтому на «как готовить» ассистент честно отвечает «шагов нет, вот рецепт по ссылке».
- **Живой человек.** Явная просьба, два «не нашёл» подряд, сбой, «не получилось» или вопрос о здоровье переводят диалог на оператора в Telegram.

## Что работает сейчас

Нужны Docker с Compose v2, make и [uv](https://docs.astral.sh/uv/) (он сам поставит Python 3.14).

```sh
make up       # Qdrant и ассистент; при первом запуске создаёт .env из .env.example
make data     # скачать датасет на зафиксированной ревизии (проверка sha256)
make index YES=1   # индекс на всём датасете (≈ 200 ₽, ≈ 80 мин); упала — ARGS="--resume <коллекция>"
make search Q="курица без лука"    # разбор вопроса LLM, фильтр и векторы, без ответа; ARGS=--no-filters — только векторы
make ask Q="есть фарш и картошка, что на ужин?"   # ответ со ссылками; ANSWER_REVIEW=false — без проверки Sonnet
make eval STAGE=retrieval          # метрики поиска на эталонном наборе
make eval ARGS="--sample 24 --runs 1"   # сквозной тест ответов; без ARGS — весь набор, 3 прогона
make test     # pytest
make lint     # ruff check, ruff format --check, mypy --strict, shellcheck
make down     # остановить стек, данные остаются в томах Docker
make help     # все команды
```

| Сервис | Адрес |
|---|---|
| Ассистент, HTTP API | http://localhost:8080/docs (`/health`, `/ask`), только с этой машины. Другой порт — `ASSISTANT_PORT` в `.env` |
| Qdrant | http://localhost:6333/dashboard |

Ключи — в `.env`: `ANTHROPIC_API_KEY` (Claude Haiku 5.5 разбирает вопрос и отвечает, Claude Sonnet 5.5 проверяет ответ и судит в eval; ключ API с platform.claude.com, подписка Claude его не даёт) и `CLOUD_RU_API_KEY` (эмбеддинги cloud.ru). `GIGACHAT_API_KEY` нужен, только если взять GigaChat вместо Claude: `LLM_PROVIDER=gigachat`. `make index` перед сборкой печатает оценку цены, сборка дороже 50 ₽ просит подтверждения `YES=1`. Индекс собирается пачками в новую коллекцию Qdrant, поиск переключается на неё, только когда все рецепты на месте; упавшая сборка оставляет недособранную коллекцию и печатает команду продолжения — повтор досылает только недостающие рецепты. Векторы лежат на диске, в памяти — их сжатая копия в int8: полный индекс — 1,6 ГБ на диске и ≈ 640–760 МБ памяти.


## Качество поиска

Эталонный набор (`evals/dataset/`) написал независимый субагент по промпту из [`evals/dataset/README.md`](evals/dataset/README.md): 83 кейса основного набора, 20 — отложенной выборки, 8 канареек судьи. Метрики поиска считает код, вопросы «по смыслу» оценивает GigaChat-3-Ultra. Сравнение моделей эмбеддингов на выборке из 10 000 рецептов, правило выбора записано до прогона ([отчёт](evals/reports/2026-11-05-models.md)):

| Модель | По названию (name_hit@5) | По ингредиентам (include_precision@5) | По смыслу (судья) | Полный индекс |
|---|---|---|---|---|
| **Giga-Embeddings-3B** (выбрана) | 0.90 | 0.85 | 0.86 | ≈ 195 ₽ |
| Giga-Embeddings-480M | 0.90 | 0.75 | 0.80 | ≈ 20 ₽ |
| Qwen3-Embedding-0.6B | 0.90 | 0.67 | 0.62 | ≈ 7,5 ₽ |
| bge-m3 | 1.00 | 0.78 | 0.74 | ≈ 4,4 ₽ |

Векторы не понимают «без»: на «курица есть, но лук я вообще не ем» все пять найденных рецептов с луком, а по вопросам «без …» больше половины топа содержит исключённый ингредиент. Поэтому поиск — не только векторы.

## Поиск с фильтрами

LLM получает вопрос, до 10 прошлых реплик диалога и словарь из 820 имён ингредиентов индекса с числом рецептов у каждого, и вызывает `search_recipes(query, include, exclude)`. Код оставляет в `include` и `exclude` только имена из словаря. Qdrant отбрасывает рецепты, где нет хотя бы одного имени из каждой группы `include` или есть имя из `exclude`, векторы ранжируют остальное по `query`.

Главная метрика — **conditions@5**: доля найденных рецептов (топ-5), где выполнены все условия кейса, проверяет код. Пороги записаны до первого прогона. Одна выборка из 10 000 рецептов, те же кейсы и тот же судья, 3 прогона на кейс ([отчёт со всеми версиями](evals/reports/2026-11-05-stage2.md)):

| | Только векторы | GigaChat-2-Pro, лучшая из трёх версий | **Claude Haiku 5.5** (effort medium) | Порог |
|---|---|---|---|---|
| conditions@5 | 0.56 | 0.89 | **0.92** | ≥ 0.90 |
| в топе есть исключённый ингредиент | 0.68 | 0.02 | 0.04 | ≤ 0.05 |
| поиск по названию (name_hit@5) | 0.90 | 0.90 | 1.00 | ≥ 0.85 |
| по смыслу (судья GigaChat-3-Ultra) | 0.84 | 0.80 | 0.86 | ≥ 0.80 |
| задержка p50 / p95 | 0.2 / 0.3 с | 1.9 / 13.8 с | 1.9 / 5.0 с | — |
| цена разбора | — | Freemium | ≈ $0.0003 за вопрос | — |

GigaChat-2-Pro за три версии промпта упёрлась в 0.85–0.89: разбивала виды одного продукта на обязательные группы («красная рыба» — сразу сёмга, форель и лосось), не раскрывала «без мяса» в список продуктов и зацикливалась на длинных списках. Claude Haiku 5.5 на том же промпте прошла все пороги. Плата за это — вопрос пользователя уходит в API Anthropic за пределы РФ; ПДн маскируются до отправки. Судьёй на этом этапе был GigaChat-3-Ultra; с этапа 3 судья — Claude Sonnet, почему — [ниже](#судья-и-ручная-разметка).

**Где поиск ошибается:**
- «борщ без мяса»: модель перечисляет десятки мясных продуктов, но не все (бульон и колбасы под другими именами проскакивают), и список от прогона к прогону разный;
- «без яиц», «без дрожжей»: по одному рецепту из пяти с формой продукта, которой нет в списке модели;
- «котлеты из индейки»: разбор верный, но часть рецептов топа — не котлеты: ранжирование векторами, а не фильтр;
- `temperature` у Claude не задаётся (API её не принимает), поэтому разбор одного вопроса может отличаться между запусками.

## Ответы со ссылками

Haiku получает найденные рецепты в помеченных блоках `<recipe id="N">` и отвечает JSON по схеме: вступление в одну фразу без фактов и до шести утверждений, у каждого — строка рецепта целиком («Молоко — 250 мл»). Проверка в два шага:

1. **Код** (`assistant/generation/citations.py`): цитата — дословная строка этого рецепта, числа утверждения — только из процитированных строк, иначе утверждение удаляется; вступление с числом убирается.
2. **Claude Sonnet** (`assistant/generation/review.py`, рубрика — та же, что у судьи eval): подтверждает ли рецепт смысл каждого утверждения. Стиль свободный — эпитеты, впечатления, вид блюда в двух словах; фактов не из рецепта быть не должно — шагов, подачи, заправки, «вместо X», другого названия. «Нет» — один раз Haiku дорабатывает утверждение по замечанию Sonnet, Sonnet проверяет исправленное, «нет» и тогда — удаляется. Второго круга нет: задержка предсказуемая.

Итоговый прогон этапа 3: весь датасет (145 954 рецепта), режим «всегда ищем», 68 кейсов эталонного набора × 3 прогона, Haiku с проверкой Sonnet в пути ответа, судья eval — Sonnet ([отчёт](evals/reports/2026-11-06-stage3-full.md), [сводка этапа со всеми версиями](evals/reports/2026-11-06-stage3.md)):

| Метрика | Значение | Порог |
|---|---|---|
| цитаты подтверждены кодом (citation accuracy) | 1.00 (1522/1522) | ≥ 0.90 |
| честный отказ на вопросы не про рецепты (abstention) | 1.00 (24/24) | ≥ 0.90 |
| ложные отказы на вопросы о рецептах | 0.01 (2/165)¹ | ≤ 0.10 |
| искал рецепты, когда нужно (tool correctness) | 0.90² | ≥ 0.90 |
| опора на рецепт по судье | 1.00 (640/643)³ | ≥ 0.85 |
| грамотность по судье | 0.84 | — |
| проверка Sonnet: на доработку / исправлено / удалено | 52 из 486 / 52 / 0 | — |
| время: разбор + ответ + проверка, медиана | 2,5 + 5,3 + 3,2 с | — |
| цена ответа | ≈ $0.001 + проверка ≈ $0.0056 | — |

¹ Оба — «скока сахара в последней»: число из названия «Шарлотка за 30 минут» код счёл выдуманным; исправлено после прогона.
² В «всегда ищем» поиск идёт и на «привет» — 15 промахов из 156 по устройству режима; «модель решает» даёт 0.99, но хуже держит факты (0.78 против 0.87 по утверждениям на одном судье).
³ Не независимая оценка: в пути ответа и в судье один Sonnet с одной рубрикой. Без проверки в пути — 0.90 по утверждениям на тех же вопросах и том же судье. Независимая оценка — канарейки и ручная разметка автора (ниже).

**Где ответ ошибается:**
- Haiku украшает фактами, которых нет в рецепте: «а сверху сухари», «кефир тут основа», «в крекерной панировке» — каждое девятое утверждение уходит на доработку, и Sonnet её принимает;
- проверка тоже ошибается: «основа из куриного филе» дошло до пользователя;
- длинное утверждение со многими количествами, у которых нет своих цитат, код отклоняет целиком — и ответ становится «не нашёл» («тирамису как в кафе» в одном из прогонов);
- на «а что такое клафути?» промпт отвечать разрешает, но кейсов на это в эталонном наборе нет.

### Судья и ручная разметка

Смысл ответа оценивает модель-судья, а ей нельзя верить на слово: её проверяют 47 канареек от независимого субагента (записи с известным ответом; вторая серия — на правила «стиль против фактов») и слепая ручная разметка автора — 69 утверждений, где судьи расходились, без вердиктов и имён судей. Каждое правило рубрики (`evals/prompts/judge_v10.md`) пришло из этой разметки или из решений автора по канарейкам, примеры в рубрике выдуманные. Канарейки по версиям рубрики: v8 — 46/48, v9 — 47/48, v10 — 47/47 (одна канарейка устарела по решению автора: «желатин — чтобы застыло» — общеизвестное о продукте).

| Судья (рубрика v8) | совпал с автором | «нет» автора поймал | канарейки | секунд на ответ |
|---|---|---|---|---|
| **Claude Sonnet 5.5** | **55/69** | **31/43** | 24/24 | 2.8 |
| GLM-5.3-Flash (cloud.ru) | 40/69 | 15/43 | 22/24 | 10.5 |

Судья другого семейства, чем генератор, был бы честнее, но кандидаты проиграли: GigaChat-3-Ultra считал ошибкой неполный список ингредиентов и пропускал настоящие ошибки (его «нет» верны в 1 из 14), DeepSeek V4 Flash не соблюдает схему ответа, GLM-5.3-Flash мягок ([сравнение](evals/reports/2026-11-06-judges-compare.md)). **Известное ограничение:** генератор, проверка в пути ответа и судья — модели одного семейства (Anthropic), а проверка и судья — одна модель с одной рубрикой. Поэтому groundedness по судье после проверки — не независимая оценка; независимая — ручная разметка автора. В промптах нет имён моделей.

**CI без ключей:** 24 сохранённых ответа Haiku перепроверяются `citations.py` на каждом PR (`tests/test_saved_answers.py`); тексты рецептов тест собирает из скачанного датасета.

## Данные

Рецепты — датасет [rogozinushka/povarenok-recipes](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) на HuggingFace, ревизия `ffaf49ee`: 146 582 рецепта с [povarenok.ru](https://www.povarenok.ru/), у каждого название, ингредиенты с количествами и ссылка на страницу. Шагов приготовления в датасете нет.

Лицензия в карточке датасета не указана. Поэтому датасет не хранится в репозитории, а скачивается с HuggingFace на зафиксированной ревизии. Проект — некоммерческая демонстрация, и каждый ответ ссылается на страницу рецепта на povarenok.ru.

## Деплой

```
git push main / Actions → CI → Run workflow
  └─ check (lint, тесты, сборка образа) ─► deploy: ssh root@сервер, checkout <SHA>, deploy/deploy.sh <SHA>
        └─ deploy.sh: ключи API из секретов GitHub → .env, make up, датасет и индекс, если их нет, проверка /health
```

Публичных портов и домена не нужно: бот сам забирает сообщения у Telegram (long polling), стек слушает только `127.0.0.1`. Сервер готовит [`deploy/bootstrap.sh`](deploy/bootstrap.sh) (один раз, от root): ставит Docker, клонирует репозиторий в `/opt/recipes-llm`, дописывает ключ деплоя в `authorized_keys` root и создаёт `.env`. Секреты environment `prod` в GitHub: `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `ANTHROPIC_API_KEY`, `CLOUD_RU_API_KEY`, `GIGACHAT_API_KEY`.
