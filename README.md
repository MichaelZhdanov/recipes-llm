# Recipes LLM

ИИ-ассистент по рецептам в Telegram. Он подбирает рецепты из [датасета povarenok.ru](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) по вопросу на обычном языке («что-нибудь с курицей, но без молока»), отвечает со ссылками, которые проверяет код, смотрит остатки продуктов в Grocy и передаёт сложные обращения живому человеку в том же Telegram.

> **Статус: этап 5 — передача живому человеку.** Бот [@recipes_llms_bot](https://t.me/recipes_llms_bot) отвечает в личных сообщениях, помнит разговор («а без сахара?») и даёт ссылку «способ приготовления» на страницу рецепта ([бот](#telegram-бот)). GLM-5.1 (cloud.ru, данные в РФ) разбирает вопрос в фильтры, ищет по всем 145 954 рецептам и отвечает живым языком утверждениями с дословными строками рецепта; код проверяет цитаты и числа. До 2026-11-07 ответ писал Claude Haiku, а Claude Sonnet проверял смысл каждого утверждения до отправки; API Anthropic закрыли, замены проверке не нашлось, и строгость перешла в промпт ответа ([переезд на cloud.ru](#переезд-на-cloudru)). Поиск с фильтрами выполняет условия «с чем и без чего» у 92 % найденных рецептов против 56 % у одних векторов ([поиск с фильтрами](#поиск-с-фильтрами)). Когда помочь может только человек — не получилось, непонятен рецепт, самочувствие, ошибка в данных или просьба, — бот передаёт разговор повару-консультанту в группу операторов Telegram и дальше пересылает сообщения в обе стороны ([передача человеку](#передача-человеку)). Каркас перенесён из прошлого проекта ассистента поддержки Paperless-ngx; история git сохранена целиком.

## Как это устроено

```
Telegram ─► бот: история (10 реплик) ─► разбор вопроса: GLM-5.1 → search_recipes(запросы[1–4], include[], exclude[])
                              ├─ имена из словаря индекса: «картошка» → «картофель»
                              ├─ фильтр Qdrant: все include есть, ни одного exclude
                              └─ векторы: похожесть по названию и смыслу, топ-5 из 145 954
         ─► ответ GLM-5.1 (recipes_v4): выбрать подходящие рецепты, вступление + утверждения,
            у каждого — дословная строка рецепта; перед ответом — самопроверка по 8 пунктам
         ─► код: цитата — целая строка рецепта, числа — только из неё; иначе утверждение удаляется
         ─► бот: ссылка «способ приготовления», если страница отвечает 200; 👍/👎
передача человеку ─► группа операторов: одна тема — одно обращение, бот пересылает сообщения в обе стороны
```

- **Фильтры, а не только векторы.** «Без молока» векторный поиск не понимает. Модель разбирает вопрос в списки «с чем» и «без чего», а Qdrant отбрасывает неподходящие рецепты до ранжирования.
- **Стиль свободный, факты — только из рецепта.** Ответ живой, на «вы», с эпитетами и эмодзи, но каждое утверждение опирается на строку рецепта, и это проверяет код. Шагов приготовления в датасете нет: под рецептом — ссылка на его страницу на povarenok.ru. Шаги от ИИ для рецептов без страницы показываются, только если их проверяет вторая модель; сейчас её нет, и такой кнопки тоже.
- **Живой человек.** Явная просьба, «не получилось», непонятный рецепт, самочувствие или ошибка в данных переводят диалог на оператора в Telegram; после сбоя, двух «не нашёл» подряд и 👎 «не получилось» бот предлагает позвать повара кнопкой. Аллергия, названная как условие подбора, — не повод: это обычный поиск «без».

## Что работает сейчас

Нужны Docker с Compose v2, make и [uv](https://docs.astral.sh/uv/) (он сам поставит Python 3.14).

```sh
make up       # Qdrant и HTTP API (+ бот при COMPOSE_PROFILES=api,bot); при первом запуске создаёт .env
make data     # скачать датасет на зафиксированной ревизии (проверка sha256)
make index YES=1   # индекс на всём датасете (≈ 200 ₽, ≈ 80 мин); упала — ARGS="--resume <коллекция>"
make search Q="курица без лука"    # разбор вопроса LLM, фильтр и векторы, без ответа; ARGS=--no-filters — только векторы
make ask Q="есть фарш и картошка, что на ужин?"   # ответ со ссылками
make eval STAGE=retrieval          # метрики поиска на эталонном наборе
make eval ARGS="--sample 24 --runs 1"   # сквозной тест ответов; без ARGS — весь набор, 3 прогона
make test     # pytest
make lint     # ruff check, ruff format --check, mypy --strict, shellcheck
make down     # остановить стек, данные остаются в томах Docker
make help     # все команды
```

| Сервис | Профиль | Адрес |
|---|---|---|
| Ассистент, HTTP API | `api` | http://localhost:8080/docs (`/health`, `/ask`), только с этой машины. Другой порт — `ASSISTANT_PORT` в `.env` |
| Telegram-бот | `bot` | порта нет: long polling. Нужен `TELEGRAM_BOT_TOKEN` (@BotFather) |
| Qdrant | всегда | http://localhost:6333/dashboard |

Что поднимает `make up`, задаёт `COMPOSE_PROFILES` в `.env`: по умолчанию `api`, с ботом — `api,bot`.

Ключи — в `.env`: `CLOUD_RU_API_KEY` — эмбеддинги и GLM-5.1, который разбирает вопрос и отвечает (API-ключ сервисного аккаунта уровня «Проект», на балансе нужны рубли). `ANTHROPIC_API_KEY` нужен только для Claude (`LLM_PROVIDER=anthropic`, проверка `ANSWER_REVIEW=true`, судья eval по API), `GIGACHAT_API_KEY` — для `LLM_PROVIDER=gigachat`. `make index` перед сборкой печатает оценку цены, сборка дороже 50 ₽ просит подтверждения `YES=1`. Индекс собирается пачками в новую коллекцию Qdrant, поиск переключается на неё, только когда все рецепты на месте; упавшая сборка оставляет недособранную коллекцию и печатает команду продолжения — повтор досылает только недостающие рецепты. Векторы лежат на диске, в памяти — их сжатая копия в int8: полный индекс — 1,6 ГБ на диске и ≈ 640–760 МБ памяти.


## Качество поиска

Эталонный набор (`evals/dataset/`) написал независимый субагент по промпту из [`evals/dataset/README.md`](evals/dataset/README.md): 83 кейса основного набора, 20 — отложенной выборки, 8 канареек судьи. Метрики поиска считает код, вопросы «по смыслу» оценивает GigaChat-3-Ultra. Сравнение моделей эмбеддингов на выборке из 10 000 рецептов, правило выбора записано до прогона ([отчёт](evals/reports/2026-11-05-models.md)):

| Модель | По названию (name_hit@5) | По ингредиентам (include_precision@5) | По смыслу (судья) | Полный индекс |
|---|---|---|---|---|
| **Giga-Embeddings-3B** (выбрана) | 0.90 | 0.85 | 0.86 | ≈ 195 ₽ |
| Giga-Embeddings-480M | 0.90 | 0.75 | 0.80 | ≈ 20 ₽ |
| Qwen3-Embedding-0.6B | 0.90 | 0.67 | 0.62 | ≈ 7,5 ₽ |
| bge-m3 | 1.00 | 0.78 | 0.74 | ≈ 4,4 ₽ |

Векторы не понимают «без»: на «курица есть, но лук я вообще не ем» все пять найденных рецептов с луком, а по вопросам «без …» больше половины топа содержит исключённый ингредиент. Поэтому поиск — не только векторы.

## Поиск с фильтрами

LLM получает вопрос, до 10 прошлых реплик диалога и словарь из 820 имён ингредиентов индекса с числом рецептов у каждого, и вызывает `search_recipes(query, include, exclude)`. Код оставляет в `include` и `exclude` только имена из словаря. Qdrant отбрасывает рецепты, где нет хотя бы одного имени из каждой группы `include` или есть имя из `exclude`, векторы ранжируют остальное по `query`.

Главная метрика — **conditions@5**: доля найденных рецептов (топ-5), где выполнены все условия кейса, проверяет код. Пороги записаны до первого прогона. Одна выборка из 10 000 рецептов, те же кейсы и тот же судья, 3 прогона на кейс ([отчёт со всеми версиями](evals/reports/2026-11-05-stage2.md)):

| | Только векторы | GigaChat-2-Pro, лучшая из трёх версий | **Claude Haiku 5.5** (effort medium) | Порог |
|---|---|---|---|---|
| conditions@5 | 0.56 | 0.89 | **0.92** | ≥ 0.90 |
| в топе есть исключённый ингредиент | 0.68 | 0.02 | 0.04 | ≤ 0.05 |
| поиск по названию (name_hit@5) | 0.90 | 0.90 | 1.00 | ≥ 0.85 |
| по смыслу (судья GigaChat-3-Ultra) | 0.84 | 0.80 | 0.86 | ≥ 0.80 |
| задержка p50 / p95 | 0.2 / 0.3 с | 1.9 / 13.8 с | 1.9 / 5.0 с | — |
| цена разбора | — | Freemium | ≈ $0.0003 за вопрос | — |

GigaChat-2-Pro за три версии промпта упёрлась в 0.85–0.89: разбивала виды одного продукта на обязательные группы («красная рыба» — сразу сёмга, форель и лосось), не раскрывала «без мяса» в список продуктов и зацикливалась на длинных списках. Claude Haiku 5.5 на том же промпте прошла все пороги. Плата за это — вопрос пользователя уходит в API Anthropic за пределы РФ; ПДн маскируются до отправки. Судьёй на этом этапе был GigaChat-3-Ultra; с этапа 3 судья — Claude Sonnet, почему — [ниже](#судья-и-ручная-разметка).

**Где поиск ошибается:**
- «борщ без мяса»: модель перечисляет десятки мясных продуктов, но не все (бульон и колбасы под другими именами проскакивают), и список от прогона к прогону разный;
- «без яиц», «без дрожжей»: по одному рецепту из пяти с формой продукта, которой нет в списке модели;
- «котлеты из индейки»: разбор верный, но часть рецептов топа — не котлеты: ранжирование векторами, а не фильтр;
- `temperature` у Claude не задаётся (API её не принимает), поэтому разбор одного вопроса может отличаться между запусками.

## Ответы со ссылками

> Этот раздел — этап 3: ответ писал Claude Haiku, проверял Claude Sonnet. Что сейчас — [переезд на cloud.ru](#переезд-на-cloudru).

Haiku получает найденные рецепты в помеченных блоках `<recipe id="N">` и отвечает JSON по схеме: вступление в одну фразу без фактов и до шести утверждений, у каждого — строка рецепта целиком («Молоко — 250 мл»). Проверка в два шага:

1. **Код** (`assistant/generation/citations.py`): цитата — дословная строка этого рецепта, числа утверждения — только из процитированных строк, иначе утверждение удаляется; вступление с числом убирается.
2. **Claude Sonnet** (`assistant/generation/review.py`, рубрика — та же, что у судьи eval): подтверждает ли рецепт смысл каждого утверждения. Стиль свободный — эпитеты, впечатления, вид блюда в двух словах; фактов не из рецепта быть не должно — шагов, подачи, заправки, «вместо X», другого названия. «Нет» — один раз Haiku дорабатывает утверждение по замечанию Sonnet, Sonnet проверяет исправленное, «нет» и тогда — удаляется. Второго круга нет: задержка предсказуемая.
3. **Тот же Sonnet — отвечает ли рецепт на вопрос.** На «что подать к красному вину» блюдо, тушённое в вине, верно описано, но не ответ: векторный поиск не отличает «к вину» от «в вине», а фильтра по составу нет (так решил автор: различать должна проверка). Такой рецепт текстом не исправить, поэтому он удаляется сразу; если по вопросу не осталось ничего или Haiku сам ответил «не нашёл», вопрос один раз разбирается заново с замечанием проверки, и поиск идёт без отклонённых рецептов. Граница (решение автора): не ответ — то, что на напитке готовят; кофейная выпечка к кофе — ответ. Рецепты итогового ответа по вопросу — 0.83 → 0.96 ([отчёт](evals/reports/2026-11-06-pairing-v6.md)); на «к красному сухому» вместо трёх блюд в вине — закуски к вину.

Итоговый прогон этапа 3: весь датасет (145 954 рецепта), режим «всегда ищем», 68 кейсов эталонного набора × 3 прогона, Haiku с проверкой Sonnet в пути ответа, судья eval — Sonnet ([отчёт](evals/reports/2026-11-06-stage3-full.md), [сводка этапа со всеми версиями](evals/reports/2026-11-06-stage3.md)):

| Метрика | Значение | Порог |
|---|---|---|
| цитаты подтверждены кодом (citation accuracy) | 1.00 (1522/1522) | ≥ 0.90 |
| честный отказ на вопросы не про рецепты (abstention) | 1.00 (24/24) | ≥ 0.90 |
| ложные отказы на вопросы о рецептах | 0.01 (2/165)¹ | ≤ 0.10 |
| искал рецепты, когда нужно (tool correctness) | 0.90² | ≥ 0.90 |
| опора на рецепт по судье | 1.00 (640/643)³ | ≥ 0.85 |
| грамотность по судье | 0.84 | — |
| проверка Sonnet: на доработку / исправлено / удалено | 52 из 486 / 52 / 0 | — |
| время: разбор + ответ + проверка, медиана | 2,5 + 5,3 + 3,2 с | — |
| цена ответа | ≈ $0.001 + проверка ≈ $0.0056 | — |

¹ Оба — «скока сахара в последней»: число из названия «Шарлотка за 30 минут» код счёл выдуманным; исправлено после прогона.
² В «всегда ищем» поиск идёт и на «привет» — 15 промахов из 156 по устройству режима; «модель решает» даёт 0.99, но хуже держит факты (0.78 против 0.87 по утверждениям на одном судье).
³ Не независимая оценка: в пути ответа и в судье один Sonnet с одной рубрикой. Без проверки в пути — 0.90 по утверждениям на тех же вопросах и том же судье. Независимая оценка — канарейки и ручная разметка автора (ниже).

**Где ответ ошибается:**
- Haiku украшает фактами, которых нет в рецепте: «а сверху сухари», «кефир тут основа», «в крекерной панировке» — каждое девятое утверждение уходит на доработку, и Sonnet её принимает;
- проверка тоже ошибается: «основа из куриного филе» дошло до пользователя;
- длинное утверждение со многими количествами, у которых нет своих цитат, код отклоняет целиком — и ответ становится «не нашёл» («тирамису как в кафе» в одном из прогонов);
- на «а что такое клафути?» промпт отвечать разрешает, но кейсов на это в эталонном наборе нет.

### Судья и ручная разметка

Смысл ответа оценивает модель-судья, а ей нельзя верить на слово: её проверяют 47 канареек от независимого субагента (записи с известным ответом; вторая серия — на правила «стиль против фактов») и слепая ручная разметка автора — 69 утверждений, где судьи расходились, без вердиктов и имён судей. Каждое правило рубрики (`evals/prompts/judge_v10.md`) пришло из этой разметки или из решений автора по канарейкам, примеры в рубрике выдуманные. Канарейки по версиям рубрики: v8 — 46/48, v9 — 47/48, v10 — 47/47 (одна канарейка устарела по решению автора: «желатин — чтобы застыло» — общеизвестное о продукте).

| Судья (рубрика v8) | совпал с автором | «нет» автора поймал | канарейки | секунд на ответ |
|---|---|---|---|---|
| **Claude Sonnet 5.5** | **55/69** | **31/43** | 24/24 | 2.8 |
| GLM-5.3-Flash (cloud.ru) | 40/69 | 15/43 | 22/24 | 10.5 |

Судья другого семейства, чем генератор, был бы честнее, но кандидаты проиграли: GigaChat-3-Ultra считал ошибкой неполный список ингредиентов и пропускал настоящие ошибки (его «нет» верны в 1 из 14), DeepSeek V4 Flash не соблюдает схему ответа, GLM-5.3-Flash мягок ([сравнение](evals/reports/2026-11-06-judges-compare.md)). **Известное ограничение:** генератор, проверка в пути ответа и судья — модели одного семейства (Anthropic), а проверка и судья — одна модель с одной рубрикой. Поэтому groundedness по судье после проверки — не независимая оценка; независимая — ручная разметка автора. В промптах нет имён моделей.

**CI без ключей:** 24 сохранённых ответа Haiku перепроверяются `citations.py` на каждом PR (`tests/test_saved_answers.py`); тексты рецептов тест собирает из скачанного датасета.

### Переезд на cloud.ru

2026-11-07 Anthropic отключил организацию автора: Haiku и Sonnet перестали отвечать. Замену искали среди моделей cloud.ru; эталон — судья-субагент Sonnet в Claude Code (рубрика `judge_v10`, на канарейках 47/47 и 34/34), а не API.

- **Кто пишет ответ** ([сравнение](evals/reports/2026-11-07-writers.md)): шаг ответа повторён на одних и тех же разобранных вопросах. Kimi K2.6 — 0.98 утверждений без нарушений, но 77 с и 6–8,5 ₽ на ответ; **GLM-5.1 low — 0.94, 9 с, 1,3–1,5 ₽**; DeepSeek-V4-Pro — 0.91, 29 с; gpt-oss-120b — 0.89, 2 с. Выбран GLM-5.1: его хостит сам cloud.ru, данные остаются в РФ.
- **Проверка перед отправкой** ([отчёт](evals/reports/2026-11-07-gate-narrow.md)): дешёвая модель с узкой рубрикой вместо Sonnet. Правило, записанное до прогона: поймать ≥ 10 из 14 нарушений эталона и зря отправить на доработку ≤ 5 % верных. Не прошёл никто: gpt-oss-120b ловит 4–7 из 14; GLM-5.1 — 12, но зря отправляет на доработку 35 из 229. Поэтому проверки нет (`ANSWER_REVIEW=false`).
- **Строгость — в промпте ответа** `recipes_v4` ([разбор ошибок](evals/reports/2026-11-07-writer-errors.md)): независимый субагент нашёл общий механизм — модель достраивает рецепт по шаблону похожего блюда («в кляре», «вместо риса», «к ним подают»; «к вину» понимает как «с вином»). В промпте — раздел «как выбрать рецепты» и самопроверка каждого утверждения по 8 пунктам. На живых вопросах «к красному сухому» — закуски, а не блюда на вине; ответ стал дольше — 15–56 с.
- **Без проверки нет и шагов от ИИ** для рецептов без страницы: кнопки «🍳 Шаги» сейчас нет.

**Известные ограничения:** v4 проверен на 5 живых вопросах, полный замер с судьёй не делался; разбор вопроса на GLM-5.1 не мерился на эталонном наборе (раньше разбирал Kimi K2.6, ещё раньше — Haiku).

## Telegram-бот

```
сообщение ─► только личные чаты; старше 10 минут — пропускается; в чате — один вопрос за раз
  ─► статус «🔎 Ищу рецепты…» → «🧑‍🍳 Подбираю лучшее…» → «🧂 Сверяю с рецептами…» и «печатает…»
  ─► ассистент в том же процессе: история диалога из SQLite (10 реплик; /new или 30 минут тишины — сброс)
  ─► страница рецепта отвечает 200? — ссылка «способ приготовления»; нет — кнопка «🍳 Шаги» (только с проверкой)
  ─► ответ встаёт на место статуса (HTML), под ним 👍/👎; после 👎 — «что не так?»
```

- **Код — в [`assistant/bot/`](assistant/bot):** `service.py` — логика без Telegram (история, страницы, оценки, шаги), `app.py` — тонкие обработчики [aiogram 3](https://docs.aiogram.dev/), `format.py` — тексты и HTML, `store.py` — SQLite, `pages.py` — проверка страницы с кэшем на неделю.
- **Шаги для рецептов без страницы** ([`generation/steps.py`](assistant/generation/steps.py)) — только когда есть проверка (`ANSWER_REVIEW=true`): после закрытия API Anthropic кнопки нет. Haiku пишет шаги только из ингредиентов рецепта (плюс вода, соль, перец, масло «по вкусу»), количества — из строк, время и температура — только если они есть в данных, иначе готовность по признакам. Sonnet проверяет по тому же стандарту и на безопасность (птица и фарш — до готовности, без домашних консервов); «нет» — одна доработка, «нет» и тогда — бот честно говорит «не смог надёжно расписать». Шаги кэшируются для всех пользователей.
- **Что хранится:** вопросы (с маскированием ПДн) и ответы для истории, оценки и причины 👎, кэш страниц и шагов. Username и имя пользователя не хранятся.
- **Тесты без сети:** обработчики проверяются на фейковом Bot API — апдейт Telegram проходит через `Dispatcher.feed_raw_update`, а сессия записывает исходящие вызовы. Токен и ключи API вычищаются из логов.
- **Локально** — `COMPOSE_PROFILES=api,bot` и токен в `.env`, потом `make up`. Один токен в двух местах даёт 409 Conflict: пока бот работает на сервере, локально нужен свой бот.

Проверка шагов ([отчёт](evals/reports/2026-11-06-steps.md), `python -m evals.steps_eval`):

| Метрика | Значение |
|---|---|
| канарейки шагов от независимого субагента: верные вердикты | 24/24 (ДИ 0.86–1.00), пропущенных ошибок 0 |
| 20 случайных рецептов: одобрено сразу / после доработки / нельзя расписать | 15 / 4 / 1 |
| время на рецепт, медиана и p95 | 10 с, 17 с |
| цена шагов одного рецепта | ≈ $0.0055 |

Все четыре доработки — по делу: трижды Haiku вписал своё время или температуру, один раз — воды больше, чем в строке рецепта; Sonnet это поймал, доработка исправила. Заготовку на зиму Haiku сам отказался расписывать.

## Передача человеку

```
вопрос ─► «позовите человека», «оператор», /human — код, сразу
       ─► разбор вопроса (тот же вызов модели, что для поиска): поле escalation —
          не получилось · непонятен рецепт · здоровье 🔴 · ошибка в данных · просьба другими словами
          → поиска и ответа нет, передача; у здоровья ещё «к врачу, экстренно — 103/112»
       ─► сбой · второй «не нашёл» подряд · 👎 «не получилось» — кнопка «🧑‍🍳 Позвать повара»
передача ─► тема «#N · повод» в группе операторов: карточка — повод, суть, последние реплики со ссылками
         ─► сообщения пользователя и оператора копируются в обе стороны (copyMessage): оператор не видит,
            кто пишет, ассистент молчит
         ─► /close в теме, закрытие темы кнопкой Telegram или /bot у пользователя → снова ассистент, 👍/👎 разговору
```

- **Смысловой повод — в том же вызове, что разбор вопроса** (`search_v5`, поле `escalation` и сводка для оператора): ни лишнего вызова, ни задержки. Отдельная классификация стоила бы +8–10 с и ≈ 1,5 ₽ на каждый вопрос.
- **Аллергия как условие — не передача** (решение автора): «у дочки аллергия на клубнику — какой десерт» — обычный поиск с аллергеном в «без чего», под ответом строка от кода: «В покупных продуктах бывают скрытые аллергены — проверьте состав на упаковке». Человеку — самочувствие и медицинская оценка: симптомы, «можно ли при гастрите», «что делать, если съел».
- **Состояние — в SQLite:** открытое обращение у чата одно (уникальный индекс), переживает перезапуск. Группа операторов — супергруппа с темами, бот — администратор с правом управлять темами (`ESCALATION_CHAT_ID`); других групп бот не слушает. Без группы или если тема не создалась — бот честно говорит, что передать сейчас не может.
- **Код — [`assistant/bot/escalation.py`](assistant/bot/escalation.py)** (фразы, карточка), `service.py` (когда передавать), `app.py` (тема и пересылка), `store.py` (обращения). Тесты — на фейковом Bot API: тема, карточка, пересылка в обе стороны, `/close`, `/bot`, сбой создания темы.

Оценка ([отчёт](evals/reports/2026-11-07-escalation.md), `python -m evals.escalation_eval`): 39 кейсов escalation — 10 из первого набора и 30 новых от независимого субагента по правилам автора; один прогон, только разбор вопроса GLM-5.1 low.

| Метрика | Значение | Порог |
|---|---|---|
| escalation F1 (передать или нет, как в боте) | **1.00** — верно 25, зря 0, пропущено 0, верно не передано 14 | ≥ 0.80 |
| повод верный, среди переданных | 25/25 | — |
| полнота «здоровье» | 6/6 | — |
| флаг аллергии, где она названа | 4/4 | — |
| разбор вопроса, медиана | 2,1 с | — |

**Ограничения:** кейсов мало и прогон один; кейсы и промпт разбора написаны по одним и тем же правилам автора, поэтому 1.00 — проверка того, что правила выполнены, а не обещание на живом трафике. Ложные передачи на обычных вопросах (другие категории набора) и живая переписка с оператором в Telegram ещё не проверены.

## Данные

Рецепты — датасет [rogozinushka/povarenok-recipes](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) на HuggingFace, ревизия `ffaf49ee`: 146 582 рецепта с [povarenok.ru](https://www.povarenok.ru/), у каждого название, ингредиенты с количествами и ссылка на страницу. Шагов приготовления в датасете нет.

Лицензия в карточке датасета не указана. Поэтому датасет не хранится в репозитории, а скачивается с HuggingFace на зафиксированной ревизии. Проект — некоммерческая демонстрация, и каждый ответ ссылается на страницу рецепта на povarenok.ru.

## Деплой

```
git push main / Actions → CI → Run workflow
  └─ check (lint, тесты, сборка образа) ─► deploy: ssh root@сервер, checkout <SHA>, deploy/deploy.sh <SHA>
        └─ deploy.sh: ключи из секретов GitHub и модель ассистента → .env, make up с профилем bot (бот и Qdrant, ждёт healthy),
                      индекс тот? (make index-check) — нет: стоп с подсказкой; сборка — только при ALLOW_INDEX_REBUILD=1
```

Публичных портов и домена не нужно: бот сам забирает сообщения у Telegram (long polling), стек слушает только `127.0.0.1`. Сервер готовит [`deploy/bootstrap.sh`](deploy/bootstrap.sh) (один раз, от root): ставит Docker, клонирует репозиторий в `/opt/recipes-llm`, дописывает ключ деплоя в `authorized_keys` root и создаёт `.env`. Секреты environment `prod` в GitHub: `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `CLOUD_RU_API_KEY`, `TELEGRAM_BOT_TOKEN`, `ESCALATION_CHAT_ID`; `ANTHROPIC_API_KEY` и `GIGACHAT_API_KEY` — если нужны эти провайдеры. Модель ассистента на сервере `deploy.sh` пишет в `.env` сам (GLM-5.1 low, без проверки), руками на сервере ничего не меняется. На сервере работает только бот: HTTP API наружу не нужен. Здоровье бота — файл-сердцебиение: раз в минуту бот спрашивает Telegram `getMe`, healthcheck Docker требует, чтобы файл был не старше трёх минут.

**Индекс на сервер — снимком, а не пересборкой.** Полная сборка на сервере — ≈ 200 ₽ эмбеддингов и около часа, а индекс уже посчитан локально. Поэтому деплой индекс сам не строит: если его нет или он не тот (`make index-check`: ревизия, модель, размер выборки), деплой останавливается с подсказкой. Снимок (`index/<коллекция>.snapshot`, ≈ 1,6 ГБ, в `.gitignore` и `.dockerignore`) загружает [`deploy/upload_index.sh`](deploy/upload_index.sh) — IP сервера и путь к ключу ssh в stdin:

```sh
printf '%s\n%s\n' <IP сервера> deploy/deploy.key | deploy/upload_index.sh   # без stdin спросит сам
```

Скрипт поднимает Qdrant на сервере, копирует снимок, восстанавливает из него коллекцию, переключает алиас `recipes` одним запросом и удаляет прежнюю коллекцию. Паспорт индекса едет внутри снимка, поэтому следующий деплой видит, что индекс тот. Пересобрать индекс на сервере можно явно: переменная Actions `ALLOW_INDEX_REBUILD=1` в environment `prod` (по умолчанию `0`) и Run workflow.
