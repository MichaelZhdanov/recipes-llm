# Recipes LLM

ИИ-ассистент по рецептам в Telegram. Он подбирает рецепты из [датасета povarenok.ru](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) по вопросу на обычном языке («что-нибудь с курицей, но без молока»), отвечает со ссылками, которые проверяет код, смотрит остатки продуктов в Grocy и передаёт сложные обращения живому человеку в том же Telegram.

> **Статус: этап 0 — чистка.** Каркас перенесён из прошлого проекта ассистента поддержки Paperless-ngx: эмбеддинги, Qdrant, клиент GigaChat, проверка цитат кодом, раннер eval с моделью-судьёй, деплой по SSH из GitHub Actions. Всё, что относилось к Paperless, убрано. Рецептов в индексе пока нет: загрузчик датасета, поиск с фильтрами и бот — следующие этапы ([план](#план)). История git сохранена целиком: в ней видно, как строился каркас.

## Как это будет устроено

```
Telegram ─► бот (вход паролем) ─► GigaChat + функции ─┬─ болтовня, не про еду → ответ без поиска
                                                      ├─ search_recipes(запрос, include[], exclude[])
                                                      │     ├─ нормализация: «картошка» → «Картофель»
                                                      │     ├─ фильтр Qdrant: все include есть, ни одного exclude
                                                      │     └─ векторы: похожесть по названию и смыслу
                                                      ├─ get_stock() → Grocy (только чтение)
                                                      └─ escalate(повод, сводка)
        ─► ответ с цитатами ─► проверка кодом: цитата есть в рецепте, иначе утверждение удаляется
        ─► ссылки на povarenok.ru
эскалация ─► группа операторов: одна тема — одно обращение, бот пересылает сообщения в обе стороны
```

- **Фильтры, а не только векторы.** «Без молока» векторный поиск не понимает. Модель разбирает вопрос в списки «с чем» и «без чего», а Qdrant отбрасывает неподходящие рецепты до ранжирования.
- **Не выдумывать.** Каждое утверждение в ответе опирается на цитату из найденного рецепта, и это проверяет код, а не модель. Шагов приготовления в датасете нет, поэтому на «как готовить» ассистент честно отвечает «шагов нет, вот рецепт по ссылке».
- **Живой человек.** Явная просьба, два «не нашёл» подряд, сбой, «не получилось» или вопрос о здоровье переводят диалог на оператора в Telegram.

## Что работает сейчас

Нужны Docker с Compose v2, make и [uv](https://docs.astral.sh/uv/) (он сам поставит Python 3.14).

```sh
make up       # Qdrant и ассистент; при первом запуске создаёт .env из .env.example
make test     # pytest
make lint     # ruff check, ruff format --check, mypy --strict, shellcheck
make down     # остановить стек, данные остаются в томах Docker
make help     # все команды
```

| Сервис | Адрес |
|---|---|
| Ассистент, HTTP API | http://localhost:8080/docs (`/health`, `/ask`), только с этой машины. Другой порт — `ASSISTANT_PORT` в `.env` |
| Qdrant | http://localhost:6333/dashboard |

`make ask` и `make search` пока отвечают «индекс не построен»: `make index` вернётся вместе с загрузчиком рецептов на этапе 1. Ключи для них — `CLOUD_RU_API_KEY` (эмбеддинги cloud.ru) и `GIGACHAT_API_KEY` (генерация) в `.env`.

## Данные

Рецепты — датасет [rogozinushka/povarenok-recipes](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) на HuggingFace, ревизия `ffaf49ee`: 146 582 рецепта с [povarenok.ru](https://www.povarenok.ru/), у каждого название, ингредиенты с количествами и ссылка на страницу. Шагов приготовления в датасете нет.

Лицензия в карточке датасета не указана. Поэтому датасет не хранится в репозитории, а скачивается с HuggingFace на зафиксированной ревизии. Проект — некоммерческая демонстрация, и каждый ответ ссылается на страницу рецепта на povarenok.ru.

## Деплой

```
git push main / Actions → CI → Run workflow
  └─ check (lint, тесты, сборка образа) ─► deploy: ssh root@сервер, checkout <SHA>, deploy/deploy.sh <SHA>
        └─ deploy.sh: ключи API из секретов GitHub → .env, make up, проверка /health
```

Публичных портов и домена не нужно: бот сам забирает сообщения у Telegram (long polling), стек слушает только `127.0.0.1`. Сервер готовит [`deploy/bootstrap.sh`](deploy/bootstrap.sh) (один раз, от root): ставит Docker, клонирует репозиторий в `/opt/recipes-llm`, дописывает ключ деплоя в `authorized_keys` root и создаёт `.env`. Секреты environment `prod` в GitHub: `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `CLOUD_RU_API_KEY`, `GIGACHAT_API_KEY`.
