# Recipes LLM

ИИ-ассистент по рецептам в Telegram. Он подбирает рецепты из 145 954 рецептов [povarenok.ru](https://www.povarenok.ru/) по вопросу на обычном языке («что-нибудь с курицей, но без молока»), отвечает со ссылками, которые проверяет код, ищет «из того, что есть дома» по складу Grocy и передаёт сложные обращения живому человеку в том же Telegram.

Бот — [@recipes_llms_bot](https://t.me/recipes_llms_bot). Проект демонстрационный: ассистент по базе знаний от идеи до работающего сервиса — с передачей человеку, интеграцией с внешней системой, защитой персональных данных, метриками качества и деплоем по push.

Живые метрики — [Grafana](https://grafana.ferdinand9.dpdns.org/), вход `devops` / `devops` (учётка только на просмотр): дашборды [«Recipes LLM»](https://grafana.ferdinand9.dpdns.org/d/recipes-llm/recipes-llm) — вопросы, время ответа, токены и рубли, отказы, передачи человеку, оценки — и [«Сервер»](https://grafana.ferdinand9.dpdns.org/d/recipes-server/server) — CPU, память, диск, трафик, входы по SSH и баны fail2ban.

| Задача | Как решено |
|---|---|
| ассистент по базе знаний (RAG, tool calling) | модель разбирает вопрос в вызов `search_recipes`, Qdrant ищет с фильтрами, ответ — с цитатами, которые проверяет код |
| передача сложных обращений человеку | поводы ловят код и модель; разговор уходит в тему группы операторов в Telegram |
| интеграция с внешней системой | склад продуктов Grocy по REST API — только чтение, ключ пользователя без прав |
| безопасность | маскирование ПДн до любого внешнего API, защита от инъекций кодом, лимит частоты, журнал с псевдонимами |
| качество | кейсы от независимого субагента, метрики кодом и судьёй, отчёты в [`evals/reports/`](evals/reports) |
| эксплуатация | метрики Prometheus, Grafana, алерты в Telegram, CI с Trivy-гейтом, деплой по push |

## Попробовать в боте

- «что-нибудь с курицей, но без молока» — поиск с условием «без»;
- после ответа — «а во втором сколько муки?»: бот помнит разговор;
- «в холодильнике есть фарш, картошка, сыр и сметана — что приготовить?» — подбор из перечня, а не рецепт сразу со всем;
- «у дочки аллергия на орехи — какой торт?» — аллерген уходит в «без чего», под ответом — напоминание о скрытых аллергенах;
- `/grocy`, затем вопрос и кнопка «🧺 Из того, что есть» — рецепты из демо-склада;
- «позовите человека» или «тошнит после грибов» — передача оператору; на самочувствие бот сразу пишет «к врачу, экстренно — 103/112».

## Запуск

Нужны Docker с Compose v2, make и [uv](https://docs.astral.sh/uv/) (сам поставит Python 3.14) и API-ключ [cloud.ru Foundation Models](https://cloud.ru/) — сервисный аккаунт уровня «Проект», на балансе рубли: на нём эмбеддинги и LLM.

```sh
git clone https://github.com/MichaelZhdanov/recipes-llm && cd recipes-llm
make .env              # .env из .env.example со случайными секретами; впишите CLOUD_RU_API_KEY
make up                # Qdrant, HTTP API и склад Grocy с демо-остатками
make index-download    # готовый индекс из релиза GitHub: 1,7 ГБ, бесплатно
make ask Q="есть фарш и картошка, что на ужин?"
```

Бот локально — `TELEGRAM_BOT_TOKEN` своего бота и `COMPOSE_PROFILES=api,bot` в `.env`, затем `make up`. Токен прод-бота локально не подойдёт: один токен в двух местах даёт 409.

| Команда | Что делает |
|---|---|
| `make up` / `make down` | поднять / остановить стек; данные остаются в томах Docker |
| `make index-download` | индекс из [релиза `index`](https://github.com/MichaelZhdanov/recipes-llm/releases/tag/index); индекс уже тот — ничего не делает |
| `make index YES=1` | собрать индекс заново: ≈ 200 ₽ и ≈ 80 мин; после сборки сам выкладывает его в релиз (нужен `gh` с правом записи) |
| `make data` | датасет с HuggingFace (sha256 сверяется) — для сборки индекса и тестов |
| `make ask Q=…` / `make search Q=…` | ответ со ссылками / только найденные рецепты, без ответа |
| `make test` / `make lint` | pytest без сети / ruff, mypy --strict, shellcheck |
| `make eval` | эталонный набор, отчёт — в `evals/reports/` |
| `make trivy` | Trivy-гейт локально |
| `make gaps` | с чем бот не справился: «не нашёл», 👎, передачи — по SQLite бота |
| `make help` | все команды |

Адреса (только с этой машины): HTTP API — http://localhost:8080/docs, Qdrant — http://localhost:6333/dashboard, Grocy — http://localhost:9283 (`admin` / `GROCY_ADMIN_PASSWORD` из `.env`), Grafana — http://localhost:3000 (профиль `observability`).

## Как работает

```
Telegram ─► бот: aiogram, long polling; SQLite — история (10 реплик), оценки, обращения
  ├─ «позовите человека», /human — код ─────────────────────────────────────► оператор
  ├─ разбор вопроса — GLM-5.1: search_recipes(запросы, include, exclude) и поле escalation
  │    └─ смысловой повод: не получилось, непонятен рецепт, здоровье, ошибка в данных ─► оператор
  ├─ поиск: имена → словарь индекса («картошка» → «картофель»), фильтр Qdrant
  │    (все include, ни одного exclude), векторы ранжируют, топ-5
  │    └─ «из того, что есть»: код читает склад Grocy, остаются рецепты только со склада
  ├─ ответ — GLM-5.1: вступление и утверждения, у каждого — дословная строка рецепта
  ├─ проверка кодом: цитата есть в рецепте, числа — из неё, ссылки — только povarenok.ru
  └─ сообщение: рецепты со ссылками, «📖 Шаги с фото» со страницы рецепта, 👍/👎
оператор ─► тема «#N · повод» в группе операторов, сообщения копируются в обе стороны
```

- **Поиск с фильтрами.** Векторный поиск не понимает «без молока»: у одних векторов условия «с чем и без чего» выполнены у 56 % найденного. Модель разбирает вопрос в списки «с чем» и «без чего» по словарю индекса, Qdrant отбрасывает лишнее до ранжирования — 92 %. Перечень «что есть дома» — набор, из которого выбирать, а не обязательный состав.
- **Ответ без выдумок.** Стиль свободный, факты — только из рецепта. Утверждение без подтверждённой цитаты код удаляет; ничего не осталось — честное «не нашёл» с подсказкой. Шагов в датасете нет: под рецептом — ссылка на страницу, а кнопка «📖 Шаги с фото» присылает шаги с этой страницы.
- **Модели.** GLM-5.1 на cloud.ru (данные в РФ) разбирает вопрос и пишет ответ; выбрана сравнением: 0.94 утверждений без нарушений, 9 с и 1,3–1,5 ₽ на шаг ответа ([отчёт](evals/reports/2026-11-07-writers.md)). Эмбеддинги — Giga-Embeddings-instruct-3B, выбраны из шести вариантов по правилу, записанному до прогона ([отчёт](evals/reports/2026-11-05-models.md)). Второй модели, проверяющей смысл, нет: API Anthropic закрыт, а дешёвая проверка не прошла порог ([отчёт](evals/reports/2026-11-07-gate-narrow.md)) — строгость перенесена в промпт с самопроверкой. Ответ — 25–65 с и ≈ 2–3 ₽.
- **Передача человеку.** Явная просьба — кодом, сразу. Смысловой повод — поле в том же вызове, что разбор вопроса: ни лишнего запроса, ни задержки. После сбоя, двух «не нашёл» подряд и 👎 «не получилось» бот предлагает кнопку «Позвать повара». Аллергия как условие подбора — не повод. Оператор не видит, кто пишет; `/close` возвращает ассистента.
- **Склад Grocy** — внешняя система, отдельный compose-проект. Только чтение: у адаптера один метод `GET /api/stock`, ключ — пользователя без прав (запись получает 403). Смотреть ли склад, выбирает пользователь кнопкой; остатки читает код, а не модель.
- **Безопасность.** ПДн (e-mail, телефоны, документы, карты) маскируются до модели, эмбеддингов, базы и журнала. Рецепты, склад и реплики попадают к модели в помеченных блоках как данные; то, что модель напишет, проверяет код, поэтому успешная инъекция не дойдёт до пользователя ни ссылкой, ни выдуманным фактом. Лимит — 10 вопросов за 10 минут и 50 в сутки. В журнале вместо chat_id — псевдоним (HMAC).
- **Наблюдаемость.** JSON-логи с `request_id`; метрики Prometheus — вопросы, время по стадиям, токены и рубли, отказы, передачи, оценки; дашборды Grafana по HTTPS; алерты в группу операторов — кончились рубли на cloud.ru, серия сбоев, бот молчит, Grocy недоступен, диск, всплеск входов по SSH.

## Качество

Кейсы пишет независимый субагент по промпту из [`evals/dataset/README.md`](evals/dataset/README.md), пороги записаны до прогона. Что можно — считает код; смысл оценивает судья (Claude Sonnet), а судью проверяют канарейки с известным ответом и слепая разметка автора.

| Что | Результат | На чём мерили | Отчёт |
|---|---|---|---|
| найденные рецепты выполняют условия «с чем и без чего» | 0.92 (одни векторы — 0.56) | разбор — Claude Haiku, выборка 10 000 рецептов | [этап 2](evals/reports/2026-11-05-stage2.md) |
| цитаты подтверждены кодом | 1.00 (1522/1522) | весь индекс, Haiku + проверка Sonnet | [этап 3](evals/reports/2026-11-06-stage3-full.md) |
| честный отказ не по теме / ложный отказ по теме | 1.00 / 0.01 | там же | [этап 3](evals/reports/2026-11-06-stage3-full.md) |
| утверждения ответа без нарушений | 0.94 | GLM-5.1 low, шаг ответа на сохранённых разборах | [авторы ответа](evals/reports/2026-11-07-writers.md) |
| передача человеку, F1 | 1.00 (39 кейсов) | GLM-5.1 low, один прогон | [передача](evals/reports/2026-11-07-escalation.md) |
| «из того, что есть»: строгие рецепты целиком со склада / по смыслу | 15/15 / 0.80 | GLM-5.1 low | [склад](evals/reports/2026-11-07-stock.md) |
| перечень продуктов не превращается в обязательный состав | 0 из 12, рецепты по условиям — 59/60 | разбор `search_v6` | [перечень](evals/reports/2026-11-07-pantry.md) |
| утечки, выполненные чужие инструкции | 0 из 25 | GLM-5.1 low | [безопасность](evals/reports/2026-11-07-security.md) |

Нынешний путь целиком (GLM-5.1, `search_v6`, `recipes_v6`) на основном наборе не замерялся: цифры — по частям и частью по прошлым моделям, на чём мерили — в таблице.

## Где ошибается

- Векторы ранжируют не идеально: на «котлеты из индейки» в топе бывают не котлеты.
- «Без мяса» модель раскрывает в список продуктов, но не полный: бульон и колбасы под другими именами проскакивают.
- Модель достраивает рецепт по шаблону похожего блюда («в кляре», «к ним подают»). Код ловит цитаты и числа, а смысл после закрытия API Anthropic второй моделью не проверяется.
- Строгий поиск по складу находит то, что случайно собирается из продуктов: «горячий шоколад» на вопрос про ужин.
- Длинный перечень «что есть дома» — ответ до минуты и иногда обрывается на лимите токенов.
- Маскер ПДн не знает адресов и имён.
- Передача человеку проверена на 39 кейсах за один прогон: это проверка правил, а не обещание на живом трафике.
- Alertmanager на том же сервере: если лежит весь сервер, алерта не будет.

## Деплой и CI

```
push в main ─► check: линтер, mypy, тесты, docker-compose.yml, правила алертов
           ├─► build: образ ассистента → GHCR ─► scan: Trivy-гейт
           └─► deploy после всех трёх: ssh → deploy/deploy.sh <коммит> <образ@digest>
раз в месяц ─► scan по образу, который сейчас в проде
```

- **Сервер не собирает образ:** он скачивает из GHCR ровно тот digest, который собрал и проверил CI. В GHCR сервер входит встроенным `GITHUB_TOKEN` задачи деплоя — только чтение пакетов, живёт до конца задачи; постоянного секрета для реестра нет.
- **Trivy-гейт** ([`scripts/trivy_gate.py`](scripts/trivy_gate.py)): устранимых HIGH и CRITICAL в проде быть не должно. Устранимая — та, от которой избавляет обновление: в нашем образе у неё есть исправленная версия, в стороннем — её нет в свежем выпуске. Такая находка роняет CI и печатает, что и где обновить, например готовую строку `image:` с новым тегом и digest. Неустранимые — предупреждения. Сторонние образы закреплены по digest: тег можно перезалить, digest — нет.
- **Индекс** сервер берёт из релиза так же, как любая машина (`index-download`; индекс уже тот — ничего). Пересборка — только если снимка для настроек нет и разрешено явно (`ALLOW_INDEX_REBUILD=1`); пересобранный снимок выкладывает в релиз раннер CI, а не сервер.
- **На сервере** — бот, Qdrant, Grocy, Prometheus, Grafana, Alertmanager, Caddy (HTTPS для Grafana и Grocy) и fail2ban. Публичные порты — только 80 и 443 у Caddy: бот сам забирает сообщения у Telegram. Сервер готовит [`deploy/bootstrap.sh`](deploy/bootstrap.sh); секреты environment `prod` — `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `CLOUD_RU_API_KEY`, `TELEGRAM_BOT_TOKEN`, `ESCALATION_CHAT_ID`.

## Код

```
assistant/
  bot/          Telegram: обработчики aiogram, логика без Telegram (service.py), SQLite,
                передача человеку, журнал, лимит частоты, пробелы базы, эксперимент
  tools/        search_recipes — разбор вопроса в фильтры и повод для человека
  retrieval/    эмбеддинги, Qdrant (алиас, int8), фильтры «с чем и без чего»
  generation/   адаптеры LLM (cloud.ru, Claude, GigaChat), промпты, ответ, проверка цитат
  indexing/     датасет, рецепт → точка, сборка индекса, снимок в релизе
  grocy/        клиент склада (только GET /api/stock), демо-склад
  security/     маскирование ПДн
evals/          эталонные кейсы, раннер, судья, отчёты
observability/  Prometheus, Alertmanager, Grafana
deploy/         bootstrap, деплой, Grocy, Caddy, fail2ban
```

Внешние API — свои тонкие адаптеры на httpx2 с таймаутами и повторами, без SDK: меньше зависимостей и поверхности для сканера. В тестах — заглушки, тесты не ходят в сеть. Промпты лежат в `assistant/generation/prompts/` и версионируются. Каркас перенесён из прошлого проекта (ассистент поддержки Paperless-ngx), история git сохранена целиком.

## Данные

Датасет [rogozinushka/povarenok-recipes](https://huggingface.co/datasets/rogozinushka/povarenok-recipes) на HuggingFace, ревизия `ffaf49ee`: 146 582 рецепта — название, ингредиенты с количествами и ссылка на страницу; шагов нет. Лицензия в карточке не указана, а README датасета предупреждает: по [правилам povarenok.ru](https://www.povarenok.ru/wiki/pravilorecept) права на рецепты принадлежат сайту. Поэтому датасет в репозитории не лежит, а скачивается на зафиксированной ревизии.

Готовый индекс в релизе [`index`](https://github.com/MichaelZhdanov/recipes-llm/releases/tag/index) производный от датасета: названия, ингредиенты, ссылки и векторы, без шагов, текстов и фото. Его распространение — осознанный риск демо; по требованию правообладателя снимок удаляется. Проект некоммерческий, каждый ответ ссылается на страницу рецепта на povarenok.ru.
